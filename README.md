# Regira Entities — Sample APIs

Three self-contained ASP.NET Core APIs that demonstrate how quickly [Regira Entities](https://regira.com/entities) can produce a fully functional CRUD + search backend. Each sample was **generated end-to-end by an AI agent** — no manual scaffolding, no boilerplate written by hand — driven exclusively from the [Regira MCP server](https://mcp.regira.com/mcp) documentation.

If you are evaluating the framework or looking for patterns to follow, browse any of the three projects: they intentionally avoid project-specific helpers and stay close to the raw framework surface.

For a more comprehensive, production-style reference, see the [PIM Backend](https://github.com/Regira/Regira-PIM-Backend) — the same framework applied to a multi-domain Product Information Management API with authentication, DTO polymorphism, tree queries, and more.

## Domain models

### Fleet.API — Maintenance

`Vehicle` is a fleet asset (car, van, truck, …). A vehicle can be assigned the **intervention types** it is allowed to undergo. `Supplier` is a garage or service provider; suppliers can be assigned the intervention types they are capable of performing. An `Intervention` ties a vehicle to a supplier under a specific intervention type, and may be billed on an `Invoice`.

```csharp
public class Vehicle : IEntityWithSerial, IHasTimestamps, IHasNormalizedContent
{
    public string LicensePlate { get; set; } = null!;
    public string Brand { get; set; } = null!;
    public string Model { get; set; } = null!;
    public VehicleType VehicleType { get; set; }
    public int Year { get; set; }
    public int Mileage { get; set; }

    public ICollection<VehicleInterventionType>? AllowedInterventionTypes { get; set; }
    public ICollection<Intervention>? Interventions { get; set; }
}
```

`VehicleInterventionType` and `SupplierInterventionType` are the two explicit join entities. Both are owned and synchronized by their parent through `e.Related(...)`, so no dedicated endpoints are needed.

### ShoppingList.API — Shopping

`Shopper` is a user. A shopper owns multiple `ShoppingList` instances. Each list holds `ShoppingListItem` entries, where each item references an `Article` and carries an `IsActive` toggle and a quantity. `Category` is a hierarchical tag node — articles can belong to multiple categories, and categories can have multiple parents and children (via the `RelatedCategory` self-join).

```csharp
public class Article : IEntityWithSerial, IHasTimestamps, IHasTitle,
    IHasDescription, IHasNormalizedContent, IArchivable
{
    public string Title { get; set; } = null!;
    public string? Description { get; set; }
    public string? Brand { get; set; }
    public string? Unit { get; set; }                   // kg, piece, litre …

    public ICollection<ArticleCategory>? Categories { get; set; }
}
```

A `GET /articles?q=cheese&categoryId=12&brand=ACME` is all it takes to filter the catalogue.

### Webshop.API — E-commerce

`Product` is a catalogue item with a price and a stock quantity. Products can belong to multiple `Category` nodes (many-to-many via `ProductCategory`). `Customer` is identified by a GUID. A `Customer` places an `Order` composed of `OrderLine` entries; the order `Total` and line `SubTotal` fields are computed automatically.

```csharp
public class Order : IEntityWithSerial, IHasAggregateKey, IHasTimestamps,
    IHasCode, IHasNormalizedContent
{
    public Guid CustomerId { get; set; }
    public Customer? Customer { get; set; }
    public OrderStatus Status { get; set; }
    public decimal Total { get; set; }
    public string? ShippingAddress { get; set; }

    public ICollection<OrderLine>? OrderLines { get; set; }
}
```

## How Regira Entities is used

Each sample follows the same pattern — a single `UseEntities()` call sets up global defaults and the Mapster mapping layer, then each entity is registered with `.For<>()`:

```csharp
services
    .UseEntities<WebshopDbContext>(options =>
    {
        options.UseDefaults();
        options.UseMapsterMapping();
    })
    .AddCategories()
    .AddProducts()
    .AddCustomers()
    .AddOrders();
```

Inside each domain's configuration the `.For<>()` builder wires up the query filter, sorting, includes, related collections, and the repository in one place:

```csharp
// Fleet.API — VehicleConfiguration.cs
services.For<Vehicle, VehicleSearchObject, EntitySortBy, VehicleIncludes>(e =>
{
    e.AddFilter<VehicleQueryBuilder>();
    e.SortBy((query, _) => query.OrderBy(x => x.LicensePlate));
    e.Includes((query, includes) =>
    {
        if (includes?.HasFlag(VehicleIncludes.AllowedInterventionTypes) == true)
            query = query.Include(x => x.AllowedInterventionTypes!).ThenInclude(t => t.InterventionType);
        if (includes?.HasFlag(VehicleIncludes.Interventions) == true)
            query = query.Include(x => x.Interventions!);
        return query;
    });
    e.Related(x => x.AllowedInterventionTypes);
});
```

Controllers inherit `EntityControllerBase` and expose a full CRUD + search surface with no extra code:

```csharp
[ApiController, Route("vehicles")]
public class VehicleController
    : EntityControllerBase<Vehicle, VehicleSearchObject, EntitySortBy,
                           VehicleIncludes, VehicleDto, VehicleInputDto>;
```

### Filtering via SearchObject

Each entity has a typed `SearchObject`:

```csharp
// Fleet.API
public record InterventionSearchObject : SearchObject
{
    public ICollection<int>? VehicleId { get; set; }
    public ICollection<int>? SupplierId { get; set; }
    public ICollection<InterventionStatus>? Status { get; set; }
    public bool? IsInvoiced { get; set; }
    public DateTime? MinScheduledDate { get; set; }
    public DateTime? MaxScheduledDate { get; set; }
    public decimal? MinCost { get; set; }
    public decimal? MaxCost { get; set; }
}
```

A `GET /interventions/search?status=Completed&sortBy=CostDesc&includes=15` is all it takes.

### EF Core interceptors

Three interceptors run transparently on every `SaveChanges`:

- **Primer** — stamps `Created` / `LastModified` timestamps
- **Normalizer** — fills `NormalizedContent` fields for full-text search (declared with `[Normalized]`)
- **AutoTruncate** — silently trims values that exceed the column `[MaxLength]`

### Seed data

All samples seed through the `IEntityService<>` implementations (not raw EF Core), so the full write pipeline runs exactly as it does for API requests. [Bogus](https://www.nuget.org/packages/Bogus) generates the data with a fixed seed for reproducibility.

## Running a sample

```bash
# restore & run (SQLite, no prior setup needed)
dotnet run --project Fleet.API
dotnet run --project ShoppingList.API
dotnet run --project Webshop.API

# open the interactive docs
# http://localhost:<port>/scalar
```

Each project ships a `NuGet.Config` that adds the Regira package feed alongside nuget.org. All three samples run within the **free tier** (≤ 5 simple + 2 complex entity registrations) — no license key is required. To raise the limits, set `Regira:LicenseKey` in `appsettings.json`.

## API endpoints

All entities expose the standard Regira CRUD + search surface:

| Method | Route | Action |
|---|---|---|
| `GET` | `/{entity}` | List (query-string filters) |
| `GET` | `/{entity}/{id}` | Details |
| `GET` / `POST` | `/{entity}/search` | Search **+ count** |
| `POST` | `/{entity}` | Create |
| `POST` | `/{entity}/save` | Upsert |
| `PUT` | `/{entity}/{id}` | Full update |
| `PATCH` | `/{entity}/{id}` | Partial update (JSON Merge Patch) |
| `DELETE` | `/{entity}/{id}` | Delete |
